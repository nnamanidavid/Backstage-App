# Backstage

Subscription box service which helps in pairing Nigerian indie musicians with merch (vinyl/cassette + physical
merch monthly), with a companion web app for managing subscriptions, browsing artists, and
streaming preview tracks.

**Stack:**
- Backend: Node.js + Express + PostgreSQL (`pg`), JWT auth, Stripe for payments
- Frontend: React + Vite + React Router, served by nginx
- Infra: AWS EKS, RDS Postgres, S3, ECR, Terraform, Kubernetes manifests, External Secrets Operator

## Repo structure

```
backstage/
├── backend/            Node/Express API
├── frontend/           React/Vite SPA
├── docker-compose.yml  local dev - db + backend + frontend together
├── terraform/          all AWS infrastructure
└── k8s/                Kubernetes manifests applied to the EKS cluster
```

## Running locally (no AWS needed)

```bash
docker-compose up --build
docker-compose exec backend npm run migrate   # first run only
```
- Frontend: http://localhost:8080
- Backend:  http://localhost:3000/api/artists

## Infrastructure overview

```
Internet -> ALB (public subnets) -> EKS Ingress
                                       /api/* -> backend Service  -> backend pods  -> RDS (private subnet)
                                                                                    -> S3 (via IRSA, no static keys)
                                       /*     -> frontend Service -> frontend pods (static SPA via nginx)
```

- **VPC**: public subnets (ALB only) + private subnets (EKS nodes, RDS), NAT Gateway for outbound,
  S3 Gateway Endpoint so S3 traffic from private subnets skips the NAT Gateway entirely.
- **EKS**: control plane + one managed node group (`t3.medium` x 2). OIDC provider enabled for IRSA.
- **RDS**: single-AZ Postgres, private subnets only, security group locked to EKS node SG on port 5432.
  Master password generated by `random_password`, never typed by a human, stored in Secrets Manager.
- **S3**: one bucket for cover art + preview audio. Public access fully blocked, encrypted at rest,
  versioned. Backend reads/writes via IRSA (`backstage-backend` Service Account -> IAM role), no
  static AWS keys anywhere.
- **ECR**: one repo each for backend/frontend images, immutable tags, scan-on-push, 10-image
  lifecycle policy.
- **Secrets**: AWS Secrets Manager is the source of truth. External Secrets Operator (ESO) syncs
  `backstage/rds/credentials` and `backstage/app/secrets` into native Kubernetes Secrets
  (`backstage-db-credentials`, `backstage-app-secrets`), which the backend Deployment reads via
  `secretKeyRef`. ESO authenticates via its own IRSA role - same pattern as the backend's S3
  access, different Service Account (`external-secrets-sa` in the `external-secrets` namespace).

## What still needs to exist before this fully works

- **AWS Load Balancer Controller** - not yet installed. Needed for `k8s/ingress.yaml` to actually
  provision a real ALB. Requires its own IAM role (IRSA, same pattern again) plus a Helm install.
- A few YAML fields are intentionally left blank until after `terraform apply`, since the real
  values don't exist before then:
  - `k8s/frontend-deployment.yaml` -> `image:`
  - `k8s/backend-serviceaccount.yaml` -> `eks.amazonaws.com/role-arn:`
  - ESO Helm install command -> `--set serviceAccount.annotations...`

## Build & deploy sequence

**1. Build and push images** (manual first, CI/CD later):
```bash
cd backend  && docker build -t backstage-backend:$(git rev-parse --short HEAD) .
cd frontend && docker build -t backstage-frontend:$(git rev-parse --short HEAD) \
  --build-arg VITE_API_BASE_URL=http://localhost:3000/api .
# tag + push to ECR (real repo URLs come from terraform output, after step 2)
```

**2. Provision infrastructure:**
```bash
cd terraform
terraform init
terraform apply   # prompts for stripe_secret_key if no terraform.tfvars is present
```
Local secret input: `terraform.tfvars` (gitignored) with `stripe_secret_key = "sk_test_placeholder"`.
In CI/CD: GitHub Actions Secret -> `TF_VAR_stripe_secret_key` env var, no `.tfvars` involved.

**3. Connect kubectl/helm to the new cluster:**
```bash
aws eks update-kubeconfig --region us-east-1 --name backstage-cluster
kubectl get nodes   # confirm connection before doing anything else
```

**4. Install External Secrets Operator:**
```bash
helm repo add external-secrets https://charts.external-secrets.io
helm repo update
helm install external-secrets external-secrets/external-secrets \
  --namespace external-secrets --create-namespace \
  --set serviceAccount.annotations."eks\.amazonaws\.com/role-arn"="$(terraform output -raw eso_role_arn)"
```

**5. Fill in the remaining blank YAML fields** using `terraform output`, then:
```bash
kubectl apply -f k8s/
```

**6. Tear down when done testing, to avoid ongoing cost:**
```bash
kubectl delete -f k8s/
terraform destroy
```

## Known app-level gaps (not infra - things to fix in code eventually)

- Preview track / cover art URLs in seed data point at plain `s3.amazonaws.com` URLs, which will
  stop working once the real bucket has public access blocked. Needs pre-signed URLs generated by
  the backend, or CloudFront with origin access control.
- No caching layer - every artist list request hits RDS fresh.
- Default `pg.Pool` settings, untuned for concurrent load.
- Stripe integration uses a placeholder key - real payment processing was never the focus of this
  build; the infra/secrets chain is fully exercised regardless of whether the key is real.
